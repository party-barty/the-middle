# System Architecture — The Middle

## Overview

The Middle is a web application built using a modern serverless architecture generated initially through Tempo Labs.

The application consists of a React frontend that communicates directly with a Supabase backend for database operations and authentication. The application is deployed through Vercel and managed through a GitHub repository.

Tempo originally served as an AI-assisted development environment that generated and edited the React codebase. The application now runs independently of Tempo.

## Backend

Backend services are provided by Supabase.

Supabase provides:

- PostgreSQL database
- Authentication system
- Row-level security policies
- REST and realtime APIs
- Serverless functions

The database schema is stored in two places:

supabase/migrations/  
backup.sql

These allow the database structure to be recreated at any time.

# Request Flow

Typical application request flow:

1. User opens the application in a browser.

2. The React application loads from the hosting provider.

3. The frontend initializes Supabase client credentials.

4. User actions trigger API calls.

Examples
- login
- create meetup
- fetch data
- update profile

5. Supabase processes the request.

6. Postgres returns the data.

7. Supabase returns the response to the frontend.

8. The UI updates in the browser.

---

# Authentication Flow

User authentication is handled through Supabase Auth.

Typical authentication process:

1. User submits login credentials
2. Supabase validates the user
3. Supabase returns a session token
4. The frontend stores the session locally
5. Future API requests include the session token

Row-level security policies enforce data permissions.

---

# Data Flow

Frontend → Supabase client → Supabase API → Postgres database

Data returned from the database flows back through the same path.

This architecture allows the frontend to communicate directly with the backend without a custom application server.

# Database Recovery

The database schema can be recreated using either of the following:

Method 1 — Supabase migrations

supabase db push

Method 2 — SQL snapshot

psql < backup.sql

These two recovery paths ensure the backend can always be rebuilt.

---

# Architectural Principles

The system follows several modern design principles:

Frontend-first architecture  
Serverless backend services  
Managed infrastructure  
Infrastructure cost minimization  
Portable database schema  
Source-controlled application state

These principles allow the project to remain easy to maintain and inexpensive to host.

# Architecture Status

The architecture is currently stable and suitable for paused development.

The application can be restarted at any time using the repository and database schema.

No vendor lock-in exists. The database schema can be migrated to any PostgreSQL provider if necessary.
